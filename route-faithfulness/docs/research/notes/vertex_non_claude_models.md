# Non-Claude models on Google Cloud Vertex AI (Gemini + open models) for the tool-calling faithfulness experiment — state as of 2026-11-23

Verification method: on 2026-11-23 the official doc pages were downloaded with curl and their raw text grepped, so quotes are verbatim and not model summaries. Each page's own "Last updated" stamp is given where it matters. No paid API was called.

Context that applies to every section: Vertex AI generative-AI docs have been rebranded. Pages now carry the title "Gemini Enterprise Agent Platform" (shortened to "Agent Platform"), and the old Vertex AI docs show a banner: "Vertex AI documentation is no longer being updated. Vertex AI's services are now part of Gemini Enterprise Agent Platform." ([Vertex deprecations page, last updated 2026-11-10](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations)). The API host is unchanged (`aiplatform.googleapis.com`), and so are the `/endpoints/openapi` path, ADC auth and IAM role names (`roles/aiplatform.user`).

## Q1. OpenAI-compatible Chat Completions endpoint: base URL, ADC auth and token refresh, and whether an API key or express-mode key works

### Takeaway
Use `base_url = https://aiplatform.googleapis.com/v1/projects/{PROJECT}/locations/global/endpoints/openapi` for Gemini and for the global MaaS open models. Use `https://{REGION}-aiplatform.googleapis.com/v1beta1/projects/{PROJECT}/locations/{REGION}/endpoints/openapi` for regional models; Llama 4 needs `us-east5`. Set `api_key` to an OAuth access token from Application Default Credentials (ADC) and refresh it about every hour. The docs say only Google Cloud auth works with the OpenAI library. Express-mode and Cloud API keys are documented only for the `generateContent` family of endpoints, not for `/endpoints/openapi/chat/completions`.

### Cited Findings
- Global base URL used by the Python client: `base_url=f"https://aiplatform.googleapis.com/v1/projects/{project_id}/locations/{location}/endpoints/{ENDPOINT_ID}"`. The sample sets `location = "global"` and the comment says "If you are calling a Gemini model, set the ENDPOINT_ID variable to use openapi". — [Authenticate (OpenAI libs), last updated 2026-11-20](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)
- Regional or environment-variable form from the same page: `OPENAI_BASE_URL="https://${LOCATION}-aiplatform.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/${LOCATION}/endpoints/openapi"`. Self-deployed Model Garden models use `.../endpoints/${ENDPOINT_ID}` in place of `openapi`. — [Authenticate](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)
- Raw REST path for MaaS open models: `POST https://aiplatform.googleapis.com/v1/projects/PROJECT_ID/locations/global/endpoints/openapi/chat/completions`. — [Call MaaS APIs for open models, last updated 2026-11-20](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/call-open-model-apis)
- Token acquisition as documented: `credentials, _ = default(scopes=["https://www.googleapis.com/auth/cloud-platform"]); credentials.refresh(google.auth.transport.requests.Request())`, then `api_key=credentials.token`. A code comment notes "the credential lives for 1 hour by default ... after expiration, it must be refreshed." — [Authenticate](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)
- Documented refresh pattern: an `OpenAICredentialsRefresher` wrapper. On every attribute access it checks `self.creds.valid`, calls `self.creds.refresh(...)` if the token is stale, and assigns `self.client.api_key = self.creds.token`. The CLI alternative is `export OPENAI_API_KEY="$(gcloud auth application-default print-access-token)"`. — [Authenticate](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)
- "Only Google Cloud Auth is supported using the OpenAI library in Gemini Enterprise Agent Platform." — [OpenAI compatibility, last updated 2026-11-20](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/openai)
- Express mode uses a projectless endpoint with the key sent in a header: "Use the global endpoint without a project ID or location, and pass your API key in the x-goog-api-key HTTP header ... `https://aiplatform.googleapis.com/v1/publishers/google/models/MODEL_ID:streamGenerateContent`". Express mode serves only the models in its table (gemini-3-pro-image, gemini-3.1-flash-image, gemini-3.1-pro-preview, gemini-3-flash-preview, gemini-2.5-pro/flash/flash-lite/flash-image), and "Only the models listed in the preceding table are supported in express mode." Express mode also requires a @gmail.com account; Workspace accounts must use a standard key or ADC. — [Express mode overview, last updated 2026-11-23](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/express-mode/overview); [API keys](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/api-keys)
- The express-mode REST reference lists only `{model}:generateContent`, `{model}:streamGenerateContent` and `{endpoint}:countTokens` (v1 and v1beta1). No chat/completions or `endpoints/openapi` method appears. — [Express mode API reference](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/express-mode/api-reference)
- Third-party corroboration (seen only as search snippets, not fetched): a Portkey gateway issue reports an "Expected OAuth 2 access token" error when an API key was sent to Vertex, and Zuplo's gateway docs carry a "Vertex AI doesn't accept API keys" caution. — [Portkey gateway issue #1441](https://github.com/Portkey-AI/gateway/issues/1441); [Zuplo Vertex AI docs](https://zuplo.com/docs/ai-gateway/vertex-ai)
- Enabling MaaS open models requires the Agent Platform API and the Cloud Commerce Consumer Procurement API (`cloudcommerceconsumerprocurement.googleapis.com`), clicking **Enable** on the model card in Model Garden, and the roles `roles/aiplatform.user` and `roles/consumerprocurement.entitlementManager`. — [Call MaaS APIs for open models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/call-open-model-apis)

### Inferences
- For the existing `AsyncOpenAI` harness, a simple approach is one long-lived `AsyncOpenAI(base_url=..., api_key=<token>)`. Before each request (or every ~45 minutes), check `creds.valid` or `creds.expiry`, run `await asyncio.to_thread(creds.refresh, Request())` when needed, and set `client.api_key = creds.token`. This is the documented sync wrapper adapted to async; the adaptation is mine, not Google's. At ~11k calls per model a run will likely last longer than one hour, so refresh is required.
- A Google Cloud API key, including an express-mode key (the `AQ.` prefix), should be assumed NOT to work on `/endpoints/openapi/chat/completions`. The docs say only Google Cloud auth works with the OpenAI library, and the express-mode API surface is generateContent only. If the team only has an express key, it has to use the google-genai SDK or REST `generateContent`, not the OpenAI harness.
- Use `/v1/` with `locations/global` wherever the model is global. The docs use `/v1beta1/` for regional and env-var examples and for Llama 4, so copy that exactly for `us-east5`.

### Gaps
- I found no official sentence of the form "API keys are rejected on the Chat Completions endpoint". The conclusion rests on the "only Google Cloud Auth" statement plus the absence of chat/completions from the express-mode API, so a 1-request smoke test with a key would settle it.
- I did not verify the `AQ.` key prefix format in official docs.

## Q2. Llama on Vertex Model-as-a-Service: status of Llama 3.1 8B/70B/405B, model IDs, regions, enablement, function calling, pricing, quotas

### Takeaway
Llama 3.1 (8B/70B/405B) and Llama 3.3 70B are no longer offered as managed MaaS on Vertex. Llama 3.3 70B was retired on 2026-10-21; Llama 3.1 MaaS appears to have been retired earlier, around 2026-01-15, per a third-party notice. The only managed Llama models left are Llama 4 Scout 17B-16E (`llama-4-scout-17b-16e-instruct-maas`) and Llama 4 Maverick 17B-128E (`llama-4-maverick-17b-128e-instruct-maas`). Both are GA, in `us-east5` only, support function calling, and require EULA acceptance on the model card. Prices are $0.25/$0.70 per 1M input/output tokens for Scout and $0.35/$1.15 for Maverick.

There is no Llama 3.x and no Qwen. — [Open models for MaaS, last updated 2026-11-20](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/maas/use-open-models)

Google's current deprecation pages do not list Llama 3.1 at all. The [partner model deprecations page](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/deprecations/partner-models) currently lists only Claude Sonnet 4.5.

### Inferences
- The planned "Llama-3.1 8B vs 70B, same family" contrast cannot be run on managed MaaS any more. The closest managed same-family pair is Llama 4 Scout (109B total / 16 experts) vs Llama 4 Maverick (400B total / 128 experts). Both have 17B active parameters, so the comparison is by total capacity and number of experts, not by active parameters. The paper should say this explicitly.
- Llama 4 MaaS is not a reasoning model, so no thinking control is needed. This fits the "thinking OFF" requirement more cleanly than Gemini 3.x or gpt-oss.
- Model string for the harness: `model="meta/llama-4-scout-17b-16e-instruct-maas"` with `base_url="https://us-east5-aiplatform.googleapis.com/v1beta1/projects/{P}/locations/us-east5/endpoints/openapi"`. Do not use the global URL for Llama 4.
- Rough cost: at an assumed ~3k input and ~300 output tokens per call, 11k calls is about 33M input and 3.3M output tokens. That gives about $10.6 for Scout and about $15.4 for Maverick. The token counts are assumptions; scale linearly.

### Gaps
- I found no official Google page stating the Llama 3.1 MaaS retirement date. The Jan 15, 2026 date comes from Portkey, a third party.
- Whether Llama 4 MaaS honors `tool_choice="none"`, `"required"` and named-function `tool_choice` is not documented; the only Llama note concerns llama3-405b. Smoke-test all three before the full run.
- Default RPM/TPM quotas for Llama 4 MaaS are not published on the model cards; they list only max output and context length. The general quotas page did not list MaaS open-model RPM.
- Whether temperature=0 is honored (or remapped) on Llama 4 MaaS is not documented.

## Q3. If Llama 3.1 8B (and 70B) is not MaaS: self-deploying from Model Garden with vLLM and tool calling

### Takeaway
Self-deploying is the only way to keep exactly Llama-3.1-8B/70B-Instruct on Vertex. Google's own recipe puts 8B on `g2-standard-12` with 1× NVIDIA L4, listed at about $1.15/hour, and 70B on `g2-standard-96` with 8× L4, about $9.21/hour. You pay per node-hour while the endpoint is up. Vertex's prebuilt vLLM/TGI containers support the Chat Completions API, but tool calling needs vLLM's `--enable-auto-tool-choice --tool-call-parser llama3_json` plus the Llama 3.1 JSON chat template. The documented Google recipe does not include these flags, so the team must add them.

### Cited Findings
- The Chat Completions API supports "select self-deployed models from Model Garden". The HF TGI column lists `Meta-Llama-3.1-8B-Instruct` and the vLLM column lists "Llama 3"; the page adds that "not every model deployed to these containers supports the Chat Completions API." — [Using OpenAI libraries (supported models), last updated 2026-11-23](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/overview)
- Self-deployed models are called through `.../locations/{LOCATION}/endpoints/{ENDPOINT_ID}`, and "you need to specify the endpoint ID" (`gcloud ai endpoints list`). — [Authenticate](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)
- Google's vLLM tutorial: `base_model_name` options include "Meta-Llama-3.1-8B-Instruct" and "Meta-Llama-3.1-70B-Instruct". The hardware map is: for 8b, `accelerator_type = "NVIDIA_L4"; machine_type = "g2-standard-12"; accelerator_count = 1`; for 70b, `"NVIDIA_L4"`, `"g2-standard-96"`, 8; for 405b, `"NVIDIA_H100_80GB"`, `"a3-highgpu-8g"`, 8. It requires `HF_TOKEN` and acceptance of the Meta Llama license. The sample server args use `vllm.entrypoints.api_server` with `serving_container_predict_route="/generate"`. Google's vLLM build lists "Llama 3.1/3.2 function calling parsing" as an enhancement. — [vLLM serving on Cloud GPUs, last updated 2026-11-20](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/open-models/vllm/use-vllm)
- Online-prediction node-hour prices (G2 series, default region shown, apparently us-central1): `g2-standard-8` $0.98181/h, `g2-standard-12` $1.15069/h, `g2-standard-96` $9.20552/h. "A node hour represents the time a virtual machine spends running your prediction job or waiting in an active state (an endpoint with one or more models deployed)". — [Agent Platform pricing, Prediction and explanation](https://cloud.google.com/products/gemini-enterprise-agent-platform/pricing)
- vLLM tool-calling flags for Llama 3.1: `--enable-auto-tool-choice`, `--tool-call-parser llama3_json`, `--chat-template examples/tool_chat_template_llama3.1_json.jinja`. vLLM supports `auto`, `required`, `none` and named functions. Named and `required` are "constrained with structured outputs". "Parallel tool calls are not supported for Llama 3". With `tool_choice="none"`, "vLLM includes tool definitions in the prompt by default", which `--exclude-tools-when-tool-choice-none` removes. — [vLLM docs: Tool calling](https://docs.vllm.ai/en/latest/features/tool_calling.html)
- The open-model deprecation table offers self-deploy as the official migration path for retired MaaS models, for example "Self-deploy Llama 3.3 on Model Garden". — [Open model deprecations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deprecations/open-models)

### Inferences
- For OpenAI-compatible tool calls, deploy with the OpenAI server entrypoint (`vllm.entrypoints.openai.api_server` or `vllm serve`) and the three tool flags above. Whether the Model Garden one-click "Deploy" exposes these flags is unverified, so a custom `Model.upload` with explicit `serving_container_args` is the safer route.
- The `tool_choice="none"` arm needs a decision. By default vLLM keeps tool schemas in the prompt when `none` is set, as OpenAI does. To keep that behavior consistent with GPT-4o and Claude, do not pass `--exclude-tools-when-tool-choice-none`.
- Cost and effort: 8B on one L4 at ~$1.15/h is cheap even at 10–20 endpoint-hours ($12–$25 total). 70B on 8×L4 at ~$9.21/h runs about $90 per 10 hours. It also needs a GPU quota of 8 L4 for custom model serving in the region, which new projects often lack and must request. Expect about 0.5–1 day of setup: HF token, quota request, container args, endpoint testing. **Undeploy the endpoint when idle**, because billing runs while it is deployed.
- Running Llama 3.1 8B/70B elsewhere (any OpenAI-compatible host) would keep the original plan's models but would not be "on Vertex". That is a team decision.

### Gaps
- I did not verify the exact current Model Garden prebuilt vLLM container image URI or its vLLM version, so I cannot confirm `llama3_json` parser support there.
- I did not verify which `model` string a self-deployed vLLM endpoint expects through the `/endpoints/{ENDPOINT_ID}/chat/completions` path.
- L4 serving quota defaults for a new project were not checked.

## Q4. Gemini via the OpenAI-compatible endpoint: model IDs, function calling and tool_choice, thinking off, temperature 0, pricing

### Takeaway
Current Gemini IDs are `google/gemini-3.5-flash`, `google/gemini-3.5-flash-lite`, `google/gemini-3.1-flash-lite` and `google/gemini-3.8-flash`, plus Gemini 4 variants. `gemini-2.5-flash` has passed its published retirement date (2026-10-20). Function calling works. `tool_choice` documents `none`, `auto`, `required` (ANY) and `validated`, but not a named-function object. Thinking cannot be fully disabled on Gemini 3.x. The floor is `reasoning_effort="minimal"`, which is the default on 3.5 Flash-Lite and 3.1 Flash-Lite, and 3.8 Flash's lowest level is LOW. Google calls temperature "no longer recommended" for Gemini 3 and ignores it from 3.6 onward. Gemini 3 requires thought signatures to round-trip on tool calls.

### Cited Findings
- Gemini models supported on Chat Completions: Gemini 4 Neon (+ for cyber), Gemini 4 Hydrogen, Gemini 4 Carbon (+ for cyber), Gemini 4 Argon (+ Cyber Permissive), Gemini 3.8 Flash (+ Cyber), 3.7 Flash, 3.6 Flash, 3.5 Flash-Lite, 3.5 Flash, 3.1 Pro (preview), 3.1 Flash-Lite, 3 Flash (preview), 2.5 Pro, 2.5 Flash-Lite and 2.5 Flash. — [Using OpenAI libraries, last updated 2026-11-23](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/overview)
- Model-string examples in the docs: `model="google/gemini-3.5-flash"` ([OpenAI compatibility](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/openai)) and `model="google/gemini-3.8-flash"` ([Authenticate](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/auth-and-credentials)).
- Lifecycle, GA: `gemini-3.5-flash` released May 19, 2026, retires "May 19, 2027 or later"; `gemini-3.5-flash-lite` released July 21, 2026, retires July 21, 2027 or later; `gemini-3.8-flash` released Sept 2, 2026; `gemini-3.1-flash-lite` released May 7, 2026. `gemini-2.5-flash`, `gemini-2.5-flash-lite` and `gemini-2.5-pro` all have retirement date "October 20, 2026" with replacement "gemini-3.8-flash or gemini-3.5-flash(-lite)". `gemini-3.7-flash` and `gemini-3.6-flash` retire January 28, 2027. — [Model versions and lifecycle, last updated 2026-11-23](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versions). This conflicts with the OpenAI overview and the express-mode table, which still list 2.5 Flash. The 2.5 Flash card adds: "Listed retirement dates refer to retirement of support in Gemini Enterprise Agent Platform." ([Gemini 2.5 Flash card](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/2-5-flash))
- Supported `tool_choice` values: "none", "auto", "required: Corresponds to the mode ANY in the FunctionCallingConfig", "validated: Corresponds to the mode VALIDATED ... Google-specific." Also: "If you pass any unsupported parameter, it is ignored." Tool `parameters` are specified "by using the OpenAPI specification", which "differs from the OpenAI parameters field, which is described as a JSON Schema object." — [Using OpenAI libraries](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/overview)
- `reasoning_effort` on Gemini 3 accepts `"minimal"`, `"low"`, `"medium"` or `"high"`, "which maps to the corresponding thinking_level setting for Gemini 3 models. Omitting reasoning_effort uses the model's default thinking configuration." For direct control, use `extra_body.google.thinking_config`. — [OpenAI compatibility](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/start/openai). The overview table instead gives budget mappings ("low: 1024, medium: 8192, high: 24576") and says "only one of reasoning_effort or extra_body.google.thinking_config may be specified." — [Using OpenAI libraries](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/overview)
- Thinking levels by model: 3.5 Flash supports MINIMAL/LOW/MEDIUM/HIGH, default MEDIUM. 3.5 Flash-Lite supports the same set, default **MINIMAL**. 3.1 Flash-Lite supports the same set, default **MINIMAL**. 3.8 Flash and 3.7 Flash support LOW/MEDIUM/HIGH, default MEDIUM. Gemini 4 models start at LOW. "MINIMAL requires thought signatures in multi-turn conversations; if omitted, the model returns a 400". "Setting thinking_budget on Gemini 4 models returns a 400 ... using it with Gemini 3 models can cause intermittent 400". 2.5 Flash and 2.5 Flash-Lite can turn thinking off "by setting thinking_budget to 0"; "You can't turn off thinking for Gemini 2.5 Pro." — [Thinking, last updated 2026-11-23](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking)
- "MINIMAL: Matches the 'no thinking' setting for most queries. The model may think very minimally for complex tasks like coding." — [Gemini 3.5 Flash guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-5-flash)
- "You can't turn off thinking or disable thought_signature generation for Gemini 3 and later models. Even when thinking_level is set to MINIMAL, the model generates thought_signature values and enforces signature validation for function calling." — [Thought signatures](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures)
- Temperature on Gemini 3: "The following sampling parameters are no longer recommended for Gemini 3 models: temperature, top_p, top_k. The model manages its own sampling ... Remove these parameters from all requests." For 3.6 Flash: "While they won't throw an error, the model will ignore them entirely." — [Gemini 3.5 Flash guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-5-flash). For 3.8 Flash: "Deprecated sampling parameters (temperature, top_k, top_p): These parameters are ignored by the backend"; passing `frequency_penalty`, `presence_penalty` or `candidate_count` "will throw an active API error". — [Gemini 3.8 Flash guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-8-flash)
- The model cards still list "Temperature: 0.0-2.0 (default 1.0)" for 3.5 Flash, 3.1 Flash-Lite and 2.5 Flash. — [3.5 Flash card](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-flash); [3.1 Flash-Lite card](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-1-flash-lite)
- 3.5 Flash Standard PayGo is available in "Global: global, Multi-region: us, eu", and "Chat Completions API Supported". — [3.5 Flash card](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-flash)
- Pricing per 1M tokens, Standard tier, global endpoint, ≤200K context; output includes reasoning tokens:
  - 3.5 Flash: $1.50 input / $9.00 output
  - 3.5 Flash-Lite: $0.30 / $2.50
  - 3.1 Flash-Lite: $0.25 / $1.50
  - 3.8 Flash: $0.75 / $3.75 introductory "through December 31, 2026", then $1.50 / $7.50 from January 1, 2027
  - 2.5 Flash: $0.30 / $2.50

  Non-global endpoints cost about 10% more for Gemini 3+. — [Agent Platform (Google models) pricing](https://cloud.google.com/model-garden/pricing)
- Standard PayGo throughput uses org-level usage tiers. For Gemini Flash, Flash-Lite and Hydrogen, Tier 1 ($10–$250 spend over 30 days) gets 2,000,000 TPM of prioritized throughput. "The throughput thresholds apply to requests sent to the global endpoint". Bursty traffic can still get 429s. — [Standard PayGo](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/standard-paygo)

### Inferences
- Thinking-off requirement: no current GA Gemini 3.x model can be run with thinking truly OFF. The closest is `gemini-3.5-flash-lite` or `gemini-3.1-flash-lite`, whose default is already MINIMAL, or `gemini-3.5-flash` with `reasoning_effort="minimal"`. Record `usage.completion_tokens_details.reasoning_tokens` (if returned) to show thinking stayed near zero. Gemini 2.5 Flash with `extra_body={"extra_body":{"google":{"thinking_config":{"thinking_budget":0}}}}` was the clean thinking-off, temperature-0 option, but its Vertex retirement date has passed, so do not build on it.
- Temperature-0 requirement: on 3.5 Flash and 3.5 Flash-Lite, temperature=0 is accepted but explicitly not recommended, and Google warns about degraded behavior. On 3.6, 3.7 and 3.8 Flash it is silently ignored. Either use 3.5 Flash-Lite or 3.5 Flash at temperature 0 and report it as a deviation risk, or report Gemini at default sampling with a fixed `seed` and multiple samples. Do not pick 3.8 Flash if determinism matters, because its temperature is ignored and its MINIMAL level is unavailable.
- Named-function forcing: the harness has a single tool (`read_document`), so `tool_choice="required"` (ANY) is functionally the same as naming it. Map the named-function arm to `"required"` for Gemini. Sending the named object `{"type":"function","function":{"name":"read_document"}}` is undocumented, and given "unsupported parameter ... is ignored" it may be silently dropped.
- Thought signatures: when the harness appends the assistant turn that holds `tool_calls`, it must keep each tool call's `extra_content.google.thought_signature` unchanged. Otherwise Gemini 3 returns 400. Re-sending the SDK object (`resp.choices[0].message.model_dump(exclude_none=True)`) should preserve unknown fields, because OpenAI SDK pydantic models keep extras. That is an inference about SDK behavior and should be smoke-tested. If the harness ever synthesizes a tool call the model did not generate (for example, injecting a fake read_document call), set `thought_signature` to `"skip_thought_signature_validator"`. The docs call this a last resort that hurts quality.

### Gaps
- Whether the named-function `tool_choice` object is accepted, ignored or rejected for Gemini on this endpoint is not documented.
- Whether `reasoning_effort="none"` is accepted for Gemini 3.x is not documented; only minimal, low, medium and high are listed.
- Whether `gemini-2.5-flash` still answers on Vertex after 2026-10-20 is unverified. The docs conflict, and the retirement date has passed.

## Q6. Known quirks: tool_call_id, parallel calls, the `tool` role, empty content with tool_calls, max_tokens vs max_completion_tokens, extra_body nesting

### Takeaway
Use `max_tokens`. On Gemini, `max_completion_tokens` is only an alias, and the MaaS examples use `max_tokens`. Nest Gemini-specific fields as `extra_body={"extra_body": {"google": {...}}}` when using the Python SDK. Echo back tool_call `id`s and Gemini `thought_signature`s exactly. Gemini 3.6 and later reject `frequency_penalty` and `presence_penalty` and require strict id/name matching on tool results.

### Cited Findings
- "max_completion_tokens: Alias for max_tokens." Supported message types include "System message", "User message", "Assistant message", "Tool message" and the deprecated "Function message". — [Using OpenAI libraries](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/migrate/openai/overview)
- MaaS samples use `max_tokens=MAX_OUTPUT_TOKENS`. For MaaS: "The first message must use the user role. The models operate with alternating user and assistant turns. If the final message uses the assistant role, then the response content continues immediately from the content in that message." — [Call MaaS APIs for open models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/call-open-model-apis)
- Documented SDK form for Gemini extras: `client.chat.completions.create(..., extra_body = {'extra_body': { 'google': { ... } }})`. The REST example nests `"extra_body": {"google": {"thinking_config": {"include_thoughts": true, "thinking_budget": 10000}, "thought_tag_marker": "think"}}`. — [OpenAI examples](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/migrate/openai/examples)
- In the Chat Completions examples, a Gemini tool call carries `"extra_content": {"google": {"thought_signature": "<SIGNATURE_A>"}}` next to `"id": "function-call-1"`. The tool result message is `{"role": "tool", "name": "check_flight", "tool_call_id": "function-call-1", "content": "..."}`. For parallel calls, "only the first functionCall part will contain the thought_signature", and responses must follow all calls in the same order: "Interleaving responses (FC1+signature, FR1, FC2, FR2) results in a 400 error." These examples use `"role": "model"` for the assistant turn, which looks like a doc inconsistency; `assistant` is the OpenAI-standard role. — [Thought signatures](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures)
- Gemini 3.8 and 3.6 Flash: "A FunctionResponse turn must strictly match the id, name, and execution count of the preceding FunctionCall"; "Remove any prefilled model turns from conversation histories"; `frequency_penalty`, `presence_penalty` and `candidate_count` throw errors. — [Gemini 3.8 Flash guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-8-flash); [Gemini 3.5 Flash guide (3.6 section)](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-5-flash)
- In the MaaS function-calling example, two parallel `tool_calls` share the same `"id": "get_current_weather"`, both tool messages use `"tool_call_id": "get_current_weather"`, and the assistant message has non-empty `content` alongside `tool_calls`. — [Function calling for open models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/capabilities/function-calling)
- vLLM self-deploy: "Parallel tool calls are not supported for Llama 3"; with `tool_choice="none"`, tool definitions are still included in the prompt by default. — [vLLM tool calling](https://docs.vllm.ai/en/latest/features/tool_calling.html)

### Inferences
- Harness rules:
  - Always echo `tool_call_id` exactly as returned, and never assume ids are unique; the MaaS example reuses one id.
  - Set `parallel_tool_calls` only if the docs list it. It is not in the Gemini supported-parameter table, so it is likely ignored.
  - Handle `content=None` or empty with `tool_calls`, and non-empty `content` alongside `tool_calls`.
  - Add `max_tokens` explicitly. Llama 4 MaaS caps output at 8,192.
- Treat any "unsupported parameter is ignored" case as a silent risk: assert on the response, for example that `tool_calls` is present when the forced arm is used, rather than trusting that a parameter was applied.

### Gaps
- I found no documentation of whether Vertex returns `content: null` or `""` with tool_calls for Gemini and Llama 4, whether Vertex-generated tool_call ids are unique per call, or whether `parallel_tool_calls=false` is honored by MaaS models.

### Inferences
- Methods-section caveats to record:
  - Llama 4 Scout and Maverick share 17B active parameters, so "small vs large" is total capacity (109B vs 400B), not dense size.
  - Gemini runs with MINIMAL thinking, not zero, and its temperature=0 is "not recommended" (3.5) or ignored (3.6+).

- Pre-flight smoke test, about 10 calls per model before the 11k run:
  - `tool_choice` None, "none", "required" and named (expect the named form to be ignored or rejected on Gemini, unknown on Llama 4)
  - `tool` role round-trip with the returned `tool_call_id`
  - token refresh after 60 minutes
  - `temperature=0` repeatability, by sending the same prompt 3 times

- Default Llama 4 MaaS RPM/TPM quotas are unpublished, so an 11k-call run in us-east5 may hit 429s. Throttle concurrency, for example 4–8 in flight with exponential backoff.
